# 完整护照卡片功能

## 已实现内容

客户档案详情页现在支持显示完整护照文件卡片。图片保持整页比例，不裁切、不拉伸；前端向私有 Supabase Storage 请求 900×1200、质量 72 的转换预览，适合手机查看，不提供高清原图直链。

护照卡片使用 5 分钟有效期的 signed URL。用户必须处于已登录状态，文件仍保存在私有 `passport-documents` bucket；链接过期、登录失效或网络失败时，页面显示安全提示，不会公开文件。

对于 OCR 图片，上传批次的私有 `file_path` 会随 OCR 草稿传递，并在人工确认建档时写入 `customers.passport_image_path`。应用重新启动后，会从 OCR 批次记录恢复该路径，再从客户记录加载护照卡片。

如果录入的是 PDF，客户详情显示“护照 PDF 已录入”文件卡片，提醒原始文件仍位于私有 Storage；当前版本不在详情页内嵌 PDF 阅读器。

## 交互状态

| 状态 | 页面表现 |
|---|---|
| 图片已绑定、正在请求 | 显示低分辨率图片加载指示 |
| 图片成功加载 | 显示整页比例护照预览 |
| signed URL 或网络失败 | 显示“护照图片暂时无法加载”和重新加载入口 |
| PDF 文件 | 显示 PDF 文件卡片，不公开下载链接 |
| 没有护照文件路径 | 不显示空卡片，客户详情继续显示结构化护照字段 |

## 安全边界

应用只请求私有 Storage 的短期 signed URL，未改变 bucket 的公开状态，也未把 Service Role Key 放入 Flutter。客户列表不直接显示护照原图；打开单个客户详情后才请求预览。护照原图不会写入 GitHub、APK 资源或审计日志。

## 当前限制

当前 PDF 只显示文件卡片，不在详情页内嵌阅读；后续如需要，可以单独增加受权限保护的 PDF 预览流程。真实护照图片端到端读取尚未用生产资料验证，验收时应使用完全脱敏图片，并确认 signed URL、图片转换、过期后重试和权限拒绝行为。

最近的分类、批量修改 `created_at` 和本次护照卡片源码改动仍在本地工作区，尚未推送到 GitHub，等待明确授权后再提交。
